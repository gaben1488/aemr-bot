# aemr-bot 0.2.2

Проверка имени жителя применяется при ручном вводе, передаче контакта MAX, повторном обращении и восстановлении диалога. Профильный ник больше не записывается автоматически как имя.

- Первое слово — имя из встроенного словаря 12 143 уникальных имён в кириллице. Разрешены двойные имена через дефис, если обе части известны. После имени можно указать ещё одно или два слова (фамилию/отчество без словаря). Примеры: «Анна», «Анна Петрова», «Анна Ивановна Петрова».
- Латиница, цифры, emoji, управляющие и невидимые символы, более трёх слов и строки длиннее установленного лимита отклоняются. Ввод не обрезается до подходящего имени. Регистр и пробелы нормализуются, е/ё учитываются при поиске.
- Контакт MAX разбирается по фактической модели maxapi 1.2.3: данные MAX и поля vCard проверяются отдельно. Структурированное имя vCard приводится к порядку «имя — отчество — фамилия». Контакт с известным чужим MAX ID отклоняется. Если ID отсутствует, телефон остаётся сообщённым самим пользователем, а не подтверждённым владением.
- Миграция 0027 очищает только поле некорректного имени. Пользователи, номера и содержимое обращений, сообщения, телефон, согласия и черновики не удаляются. При следующем взаимодействии требуется подходящее имя. Служебная обезличенная запись исключена из очистки.
- Запрос нового имени сохраняет прерванный шаг и допустимые отложенные данные. Проверки охватывают текст, вложения, геолокацию, повторное обращение, дополнения и устаревшие кнопки. Отписка, отзыв согласия и удаление данных не требуют имени. Если процесс оборвался во время возобновления, следующий вход завершает сохранённое действие; бот явно просит повторить новое сообщение или кнопку, чтобы не принять повтор имени за ответ следующего шага.

Словарь находится в пакете и работает без сети. Источник — набор Rustem Gareev russian-names, закреплённая ревизия 87489df, лицензия CC BY-SA 4.0; атрибуция и преобразования описаны в `bot/aemr_bot/data/NAMES_LICENSE.md`. Это широкий словарь, а не исчерпывающий перечень всех существующих имён и не проверка личности: человек может представиться любым допустимым именем. Фамилия и отчество проверяются только по форме по требованию владельца.

Обновление выполняется вручную в контуре владельца штатным способом; запуск образа выполняет `alembic upgrade head`. Очистка произойдёт при применении миграции на вашей БД, а не при публикации этого релиза. Откат миграции не восстанавливает отброшенные имена; дополнительный архив персональных данных не создаётся. Сохраняйте постоянные тома и действующий .env; не используйте `down -v` и не запускайте два экземпляра. Альтернативный автодеплой сохранён. Публикация GitHub не является развёртыванием на сервере.

Зависимости не изменены, maxapi остаётся 1.2.3. Исправления 0.2.0/0.2.1, тихо отключаемый необязательный бэкап и один сигнал на эпизод недоступности баз угроз сохраняются.

QA: позитивные/негативные имена, реальные SDK-модели контакта, повторный ввод и возобновление диалога, сохранность связанных данных при повторном выполнении миграции, включение словаря в wheel; полный pytest и PostgreSQL16 CI, миграции upgrade/check/downgrade/upgrade, Ruff, mypy, Bandit, pip-audit, shellcheck, Docker build.
