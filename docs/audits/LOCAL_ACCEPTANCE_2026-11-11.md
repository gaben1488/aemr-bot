# Локальная приёмка AEMR-bot, 11.11.2026

База: `2e320fc276e951eaa0961a75101b936f84187275`.
PR #304, #305 и #306 объединены. Последующее продолжение восстановлено из
сохранённого пакета 30 октября. До новых исправлений tree каталога bot совпал
с `6f53e5917eeb93f21bd07b814092886286779bc9`.

## Проверенное продолжение

- Пофайловые галереи черновиков жителя и оператора с проверкой прав, токена,
  редакции, состояния и защиты нового вывода после удаления данных.
- Переключение ввода между ответом и административными редакторами с паузой
  сохранённого ответа; подтверждение/отмена рассылки связаны с текущим preview.
- Предпросмотр текста настройки до сохранения; сохранение авторского приветствия
  при повторном запуске без эвристической подмены seed-текстом.
- План частей ответа, сохранение подтверждённых и недоставленных частей,
  ручная сверка без автоматического повтора неизвестной доставки.
- Очередь, SLA и XLSX различают отсутствие ответа и неизвестное время доставки;
  возобновление сохраняет оценку старого периода отдельно от нового.
- Полная история Word/XLSX, читаемая разбивка, пагинация контактов, callback-маршруты,
  синхронизация текущей технической документации, вики и инвентаризации.

## Наблюдённые проверки

Python 3.12.14, зависимости по uv.lock, отдельная PostgreSQL 16.10 с UTF8/C.utf8,
TZ=Asia/Kamchatka. Настоящие MAX/VPS и рабочие данные не использовались.

- Полный suite: **3494 passed**, без skipped, 128,37 секунды.
- Branch coverage: **84,50%** при пороге 80%.
- Ruff, MyPy (191 модуль), Shellcheck 0.10.0, staged-size и diff-check пройдены.
- Bandit: 0 medium/high. pip-audit: 79 закреплённых зависимостей,
  известных уязвимостей на момент проверки не найдено.
- Чистая БД: upgrade head → check → downgrade base → upgrade head → check.
- Существующая БД: 0041 → 0042 с сохранением текста 13 800 символов, файлов,
  истории, черновика и редакции согласия. Старые временные свидетельства остаются NULL.
- Downgrade 0042 отдельно отказал при наличии delivery_uncertain_until и
  last_activity_at; версия 0042 и данные сохранились. После удаления только
  синтетических новых свидетельств round-trip 0042 → 0041 → 0042 прошёл,
  прежние данные сохранены; alembic check не выявил расхождений.

Первый полноценный PG17-прогон дал 3493 passed / 1 failed: старая тестовая
фикстура отмены не содержала dialog_data настоящей модели User. Она дополнена
без ослабления проверок отсутствия сброса и ложной отмены. 12 целевых проверок
и последующий полный PG16-прогон прошли. Неудачные предварительные запуски
без доступной БД не считаются проверкой продукта.

Исправлены устаревшие комментарии модели и User-сервиса: они обещали ответ
после отзыва и продление хранения из-за открытого обращения, хотя текущая
логика этого не допускает. Исполняемое поведение ради комментариев не менялось.

После смены среды checkout и локальные полные логи исчезли. Код повторно
восстановлен и его bot tree **точно совпал** с проверенным
`664907964548de056046107718d54aeaf35949c1`. Числа выше подтверждены результатами
завершённых команд предыдущего запуска, а не новым прогоном в новой среде.
Полный сохранённый лог пока не восстановлен; это ограничение воспроизводимых
артефактов, а не заявление о новом запуске тестов.

## Повторная приёмка 13.11.2026

После новой смены среды восстановлен проверенный commit `5755e0e` из пакета v5.
Исполняемый код не менялся. Подтверждён пробел в сквозных проверках перехода
в меню перед операторским ответом; добавлены только две группы регрессий:

- Шесть случаев: финальный/промежуточный ответ после открытия меню из IDLE,
  паузы дополнения и при наборе другого черновика. Реальные обработчики,
  PostgreSQL, guards, журнал частей и история; только MAX заменён локальным
  fake transport. Проверены адресат, текст, история, статус, сохранность
  другого черновика, согласия и состояния подписки.
- Выборка и handler уведомления ограничены своими NEW/IN_PROGRESS без
  ANSWERED/CLOSED/очищенных записей, в том числе после 501 чужого обращения.
  Текущий интерфейс сообщает список открытых ID, не перепубликует старые карточки.

Выход в меню не является отзывом согласия. Последний остаётся отдельным
действием с действующими ограничениями автоматической доставки.

Новый запуск: PostgreSQL 16.10 (официальный source archive с проверкой SHA256),
Python 3.12.14, uv.lock, TZ=Asia/Kamchatka. **3501 passed**, без skipped,
**127,87 с**, branch coverage **84,59%**. Ruff чисто; MyPy: 191 модуль без ошибок;
Bandit: 0 medium/high. Staged-size и diff-check пройдены.
Мутационный запрет ответа в IDLE дал два ожидаемых падения, удаление SQL
user_id-фильтра дало одно: проверки чувствительны к нужным нарушениям.
Обе мутации отменены до полного прогона; production-код совпадает с v5.

Полный лог, JUnit, coverage JSON и логи адресных/мутационных проверок включены
в обновлённый сохранённый пакет. Миграции, pip-audit и Shellcheck в этом запуске
не повторялись: их результаты выше относятся к 11 ноября. Схема и зависимости
после того запуска не менялись. Настоящая доставка MAX не проверялась и из
локальных результатов не следует. Никакого трафика в действующий MAX не было.

  в просмотренных галереях, владении вводом, preview и SLA. Он не является

- Боевые клиенты MAX, доставка/недоступность файлов, VPS и эксплуатационная
  приёмка не подтверждены. Release/deploy/merge не выполнялись.

  документов и фактическая ручная обработка внешних копий остаются открытыми.
